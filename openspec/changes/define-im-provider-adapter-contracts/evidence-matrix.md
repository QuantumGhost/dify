# IM Provider Verification Evidence Matrix

`MISSING` is an intentional blocking state. A capability remains incomplete until every applicable external-execution cell points to auditable repository evidence. `N/A` means that an external operation has no applicable evidence path, such as independent cryptographic verification for an outbound API call.

## 已确认的 Provider contract notes

- DingTalk credential exchange 使用[官方 token contract](https://open.dingtalk.com/document/orgapp/api-gettoken.md)定义的 `POST /v1.0/oauth2/{corpId}/token`；官方 OpenAPI SDK 对应 symbol 为 `oauth2_1_0.Client.get_token(corp_id, GetTokenRequest)`。request body 为 `client_id`、`client_secret` 与 `grant_type="client_credentials"`，success response 为 `access_token` 与 `expires_in`。成功响应绑定 path 中的 configured CorpID；`invalid.client`、`unauthorized.client` 与 `unsupported.grant.type` 均属于 authentication failure。
- DingTalk 与 WeCom 的 inventory 只覆盖 credential、Directory 与 Basic Messaging API；removed Webhook/STREAM scope 不保留为 `N/A` 或 `MISSING` 行。
- External matrix 只统计本实现真实消费的 Provider API、connection、challenge/configuration 和 business event entry。pure local assessment、control/reconnect/stop lifecycle、negative security、sink/ACK failure 与 event-ID 边界由独立 test-only checklist 跟踪，不伪装成可由 live fixture 关闭的外部 evidence cell。
- 上述 contract 结论不补齐任何 evidence cell；真实非生产调用与脱敏 fixture 仍保持 `MISSING`。
